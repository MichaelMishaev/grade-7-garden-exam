# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

PrepX: a mobile-first Hebrew (RTL) exam-prep site for class ז׳2 at שי עגנון school, Netanya. Plain static HTML/CSS/JS with no framework, no build step, and no test or lint tooling. The only npm dependency is `postgres`, used by the optional database layer.

## Commands

```bash
npm start            # node server.mjs → http://localhost:3000 (override with PORT)
```

There is nothing to build or lint. Run `node --test *.test.mjs db/*.test.mjs` for scoring, references, the verbatim physics exam, the exam-page parity test (`physics-exam.parity.test.mjs`), the submission API (`server.test.mjs`, `server.exams.test.mjs`) and the database layer (Postgres tests skip unless `TEST_DATABASE_URL` / `E2E_DATABASE_URL` is set; `e2e/full-stack.test.mjs` needs `E2E_DATABASE_URL`). Verify changes by loading the pages in a browser (mobile viewport first; every page is `lang="he" dir="rtl"`).

## Architecture

**Two hosts serve the same files.** GitHub Pages serves the repo directly (`.nojekyll`), and Railway runs `server.mjs` (service `web`, custom domain https://hitech.agnon.online/). Static pages work on both hosts; email submission requires the Railway API. GitHub Pages calls the canonical Railway endpoint with an explicit CORS origin.

**`server.mjs` serves static files and `/api/submit-exam`.** The submission API validates the answers, keeps Resend credentials server-side, sends to a fixed teacher, deduplicates through Resend, and limits attempts. **Every exam uses this one endpoint and the same Resend account (`RESEND_API_KEY`, `RESEND_FROM_EMAIL`), sender, teacher, rate limit and origin rules.** A payload without `exam` is a Hebrew exam (garden, library): exactly 20 answers, subject `תשובות למבחן הבנת הנקרא - כיתה ז׳`, idempotency key `garden-exam/sha256({name, answers})`; keep these byte-identical (`test-fixtures/legacy-email-snapshots.json`): that format is now only for already-open old tabs, no live page sends it. Every live exam sends `exam: '<exam id>'`, which must be a key of the `exams` table in `server.mjs` (`code`, `count`, `subject`, `idempotencyPrefix`, `title`, `subtitle`); unknown values get 400. Ids and permanent test codes: `hebrew-v1-garden` HEB-001 (20), `hebrew-v2-library` HEB-002 (20), `physics-v1-assessment` PHY-001 (27); codes are never reused or changed. Table exams also send `attempt` (part of the idempotency key, so a retake is emailed again), per-answer `options`, `correctAnswer`, `reference`, `questionId`; the server measures the finish time itself, grades open answers with OpenAI (`OPENAI_API_KEY`, `ai-grading.mjs`, rubrics in `open-rubrics.mjs`, `POST /api/grade-open` for the retry) and its email shows the code, attempt, duration, AI scores. Without an AI score, answers lacking a `correct` mark are labelled `✎ ממתינה לבדיקת המורה` in the email (never on screen). Static files use GET/HEAD, only the extensions in its `types` map (`.html .css .js .svg .png`), and 404s any path segment starting with `.`. Adding a new asset type (e.g. `.webp`, `.json`, `.ico`, fonts) requires adding it to `types`, or it will 404 on Railway while still working on GitHub Pages. Responses are cached for 5 minutes.

**Cache busting is manual.** Stylesheets are linked with a version query (`styles.css?v=4`, `practice.css?v=2`). Bump the `?v=` number in every page that links a stylesheet when you change it.

**Page flow and where content lives:**
- `index.html` → subject list (static links to `subject.html?subject=<key>`).
- `subject.html` → reads `?subject=` and renders exam versions from the inline `subjects` object in its `<script>`. Add exam versions or subjects there (each variant has an `id` = exam id and its own `references`, shown as "חומר לימוד"; `practiceQuizzes` puts quiz rows inside the version). The Hebrew practice-quiz links are static markup in the same page; the physics rows are built from `subjects.physics.quizzes`.
- **References rule:** every question follows a part of its exam's study material: `ref: { id, part }` in `library-exam.js`, `physics-exam.js` and `practice.js` (garden: by index in `db/extract.mjs`). Parts must exist in the reference's `parts` list in `subject.html`; `db/extract.test.mjs` fails otherwise. Physics refs are `physics-pdf` `עמוד 1`–`עמוד 6` or `physics-site` `פרק 1`–`פרק 4` (only where the PDF does not cover the topic).
- **All exams share one flow and one look:** start (study material + name box; name required) → questions (progress, collapsible material, flag "סימון לבדיקה חוזרת") → review (blocks finishing until every question is answered) → finish: the email is sent at once, everything locks, and a read-only summary (score, topics, explanations, plain-text source lines) with a "you're done" banner replaces the old results + send button. Radio answers lock and advance after 1.5 s, typed answers use "אישור", the timer is visible, questions and options are shuffled per student. **The rules for every test (types, feedback, locking, shuffle, email, AI grading, ship gate) are in `docs/TESTING.md`, the single source of truth; where it differs from older text here, it wins.** `library-exam.html` + `library-exam.js` is the reference implementation; `physics-exam.html` copies its markup, ids, classes, labels and `<style>` block, and `physics-exam.parity.test.mjs` fails on any drift. A new exam must copy this flow too, have its own entry in the server `exams` table, tests, and the thanks flow; self-graded-only exams are not allowed.
- `library-exam.html` + `library-exam.js` → Hebrew version 2 (20 questions, choices shuffled within difficulty). Sends with no `exam` field (payload unchanged), then clears its draft, stores `library-exam-result-v1` and redirects to `thanks.html`.
- `physics-exam.html` + `physics-exam.js` + `numeric-answer.js` → the teacher שרית שרת's 27-task assessment, **verbatim** from her practice site (`physics-exam.test.mjs` compares it byte for byte with `test-fixtures/sarit-physics7-sections.json`; never edit those texts), in the library flow. Every text, option, answer and explanation stays verbatim; only the order of the tasks and of the options is shuffled per student (the test compares the data, not the display order). Choice and numeric tasks are auto-graded (numbers like her site, via `numeric-answer.js`); results show her explanations, model answers and "בדקו:" lists. Sends `exam: 'physics-v1-assessment'`, each `question` as the prompt in plain text (`plainText`: `<br>` → newline, tags removed; same one-liner in `db/submissions.mjs`), numeric answers as the number on the first line plus `דרך חישוב: …`, and `correct` on choice/numeric tasks. On success the draft stays as a locked, read-only summary (`physics-exam-draft-v1` with `sent: true`; a reload never resends), `physics-exam-result-v1` is stored, and the page shows the done banner. `thanks.html` is kept for old tabs and the garden exam's legacy result.
- `practice.html` + `practice.js` → reads `?quiz=` (`facts` | `questions` | `instructions`) and runs a self-graded quiz from the `quizzes` object in `practice.js`. Each question has `choices`, a `correct` index, and Hebrew (`he`) and English (`en`) explanations. Nothing is sent anywhere.
- `garden-exam.html` → the full 20-question open-answer exam; all logic is inline. Questions are in the inline `questions` array. On submit it POSTs JSON to `/api/submit-exam`, which emails the teacher through Resend. GitHub Pages uses `https://hitech.agnon.online/api/submit-exam`. Provider acceptance redirects to `thanks.html`; failures keep the draft.
- `thanks.html` → the end of every exam: clears `garden-exam-draft-v1`, `library-exam-draft-v1` and `physics-exam-draft-v1`, and shows the summary (`*-exam-result-v1`: times, count, partial score when sent) of the exam finished last.

**Exam drafts** are kept in `sessionStorage` under `garden-exam-draft-v1` (also `library-exam-draft-v1`, `physics-exam-draft-v1`; never reuse a key). Each key appears in its exam page and in `thanks.html`; change both together. Privacy line on every exam: the draft stays in this tab; name and answers go to the teacher automatically when the student finishes (via Resend), and open answers are checked by an AI service (`docs/TESTING.md` §9). Server-side storage is optional in code and off unless the flags are set (production needs them for practice history and AI-score persistence): with `DATABASE_URL` and `DB_WRITE_SUBMISSIONS=1`, submissions (name and answers) are saved to Postgres and kept with no automatic deletion.

**Database (optional, off by default):** `db/` holds the Postgres schema (`001_init.sql`; `002_references.sql` adds `study_references` and `questions.reference_id/reference_part`), `extract.mjs` (reads questions from the page sources, which remain the source of truth), `seed.mjs`, `verify.mjs` and the server-side layer. Flags: `DATABASE_URL`, `DB_WRITE_SUBMISSIONS=1` (save before emailing; a DB failure or >2s delay must never stop the email), `DB_READ_API=1` (`/api/subjects|quizzes|exams`, `/api/health`). With the flags off, behavior must stay identical to the no-database server. Migrations are additive only; never delete database rows without explicit permission and a backup. After changing any question text, re-run `npm run db:seed` and `npm run db:verify`. `content-api.js` loads API content with inline fallback; practice, subject and all three exam pages use the API by default (`?source=inline` forces inline). Exam pages use API questions only when identical to the inline arrays (order, ids, prompts, answers, references), so the inline data stays authoritative. Never log the `postgres` error object (it can contain parameters); log `error.code` only.

**Resend configuration:** `RESEND_API_KEY` and `RESEND_FROM_EMAIL` are private Railway variables. `APP_ORIGIN` is the canonical app origin; set `NODE_ENV=production` in production. Never log student answers or credentials. Local checks mock Resend (`node --test server.test.mjs server.exams.test.mjs`; browser checks must mock it too, e.g. `createApp({ env, sendFetch: mock })`, and never call https://hitech.agnon.online/api/submit-exam); only a real provider delivery event or inbox receipt proves delivery.

**Styling:** `styles.css` (index/subject) and `practice.css` (practice) define CSS custom properties at the top (green palette, `--ease-out`). Both include a `prefers-reduced-motion` block that removes movement; keep new animations inside that contract. `garden-exam.html`, `library-exam.html`, `physics-exam.html` (library's block verbatim plus a small physics-only block) and `thanks.html` carry their own inline styles.
